# 1号卡 DDR 全量读写异常记录

日期：2026-09-29

## 1. 测试对象

- 显卡：标号 **1**
- DDR 总容量：**4 GiB**
- 颗粒数量：**2**
- 单颗容量：**2 GiB**
- 地址映射：两颗 DDR 按地址空间连续映射，顺序为 **DDR0 -> DDR1**
- 测试方式：对 4 GiB 地址空间进行全量 32-bit 读写校验
- 循环次数：**200 轮**
- 读取策略：写入后连续读取两次进行校验

按当前连续映射关系：

- DDR0：低 2 GiB 地址空间
- DDR1：高 2 GiB 地址空间

## 2. 总体现象

200 轮测试中：

- **189 轮完全通过**
- **11 轮出现错误**
- 总错误记录：**44,286 次**
- 其中 **44,280 次**集中于 `0x021xxxxx`
- 仅剩 **6 次**不属于该主错误模式

因此错误并非均匀分散在 4 GiB 地址空间中，而是具有极强的地址集中性。

由于 `0x021xxxxx` 位于低 2 GiB 地址空间，当前可以确认：

> 主错误全部发生在 DDR0 地址空间。

这里暂时只能确认“DDR0 路径强相关”，尚不能直接断言 DDR0 颗粒本体损坏；仍需通过换卡/交叉实验区分颗粒、PHY、PCB、控制器配置及其他访问源等因素。

## 3. 错误数据特征

发生错误时：

- 第一次读取值错误；
- 第二次读取值与第一次 **完全相同**；
- XOR 值无明显固定 bit 规律，表现较随机。

因此当前现象不像简单的瞬时读采样抖动；错误数据在连续两次读取之间保持稳定。

## 4. 地址分布

### 4.1 `0x0210xxxx ~ 0x021Fxxxx`

按 64 KiB 地址段统计：

| 地址前缀 | 错误次数 |
|---|---:|
| 0x0210 | 0 |
| 0x0211 | 4320 |
| 0x0212 | 4320 |
| 0x0213 | 4320 |
| 0x0214 | 4320 |
| 0x0215 | 4320 |
| 0x0216 | 4320 |
| 0x0217 | 4320 |
| 0x0218 | 4320 |
| 0x0219 | 4320 |
| 0x021A | 4320 |
| 0x021B | 1080 |
| 0x021C | 0 |
| 0x021D | 0 |
| 0x021E | 0 |
| 0x021F | 0 |

合计：

```text
10 × 4320 + 1080 = 44280
```

### 4.2 `0x0211xxxx` 内继续细分

对 `0x02110xxx ~ 0x0211Fxxx` 按 4 KiB 地址段统计，仅以下四段出现错误：

```text
0x02113xxx    1080
0x02117xxx    1080
0x0211Bxxx    1080
0x0211Fxxx    1080
```

其余 4 KiB 地址段均为 0。

上述异常段之间严格相差：

```text
0x4000 = 16 KiB
```

说明主错误模式具有明显的 **16 KiB 周期性**。

## 5. 完整地址与 offset 统计

进一步统计发现：

### 5.1 完整错误地址重复次数

对完整错误地址执行 `sort | uniq -c` 后，主模式中的完整地址重复次数均为：

```text
9
```

这说明大量错误并非每次落在新的随机地址，而是同一批固定地址在多个异常轮次中重复出现。

### 5.2 按 `0x4000` 折叠后的 offset

将所有错误地址按：

```text
addr & 0x3FFF
```

折叠到同一个 16 KiB 窗口后：

- 主体 offset 的累计次数均为 **369**
- 其中一个 offset 为 **375**

其中：

```text
369 = 41 × 9
375 = 369 + 6
```

而：

```text
44280 / 369 = 120
```

因此当前主模式高度符合以下结构：

- 共 **41 个**按 `0x4000` 间隔排列的异常区域；
- 每个区域存在 **120 个相同 offset**；
- 每个完整地址累计重复出现 **9 次**；
- `41 × 120 × 9 = 44280`，与主错误总数完全一致。

另外 6 次非主模式错误很可能解释了单个 offset 从 369 增加到 375，但该点尚未单独验证。

## 6. 当前判断

目前可以确认的事实：

1. 错误具有高度确定性的地址分布，并非 4 GiB 空间中的随机散布。
2. 44,280 / 44,286 次错误属于同一个高度规则的主模式。
3. 主错误全部位于 DDR0 地址空间。
4. 主模式具有严格的 `0x4000`（16 KiB）周期。
5. 同一批完整地址重复出现 9 次。
6. 16 KiB 周期内存在相同的一组固定 offset。
7. 连续两次读取错误地址时，错误值保持一致。

因此当前继续单纯调整 DDR timing / Vref 等参数的优先级较低。

现阶段仍不能仅凭这些现象断言“DDR0 颗粒本体损坏”，因为以下方向仍可能产生类似现象：

- DDR0 颗粒本体异常；
- DDR0 对应 PHY / 控制器路径；
- DDR0 PCB / 供电；
- 地址映射或访问逻辑；
- Cache / MMU 相关问题；
- DMA、GPU 或其他 master 周期性访问/覆盖特定区域；
- 测试区域与其他 firmware buffer / reserved memory 冲突。

## 7. 下一步

暂停继续对 1 号卡做参数调整。

下一步更换为 **标号 2 的显卡**，保持测试条件尽可能一致，重复完整测试：

- 相同固件；
- 相同 DDR 参数；
- 相同测试程序；
- 相同读写 pattern；
- 相同 200 轮测试规模；
- 保留完整错误日志。

重点对比：

1. 2 号卡是否仍出现 `0x021xxxxx` 集中错误；
2. 是否仍出现 `0x4000` 周期；
3. 是否仍为相同的 120 个 offset；
4. 是否仍表现为固定完整地址重复；
5. 若 2 号卡完全正常，则进一步提高 1 号卡硬件侧问题的优先级；
6. 若 2 号卡复现相同地址模式，则优先排查软件、地址占用、控制器配置及其他 master 对该区域的访问。

## 8. 当前阶段结论

> 1 号卡的异常已经表现出高度规则的 DDR0 地址相关特征。现阶段继续微调参数的诊断收益较低，优先使用 2 号卡进行同条件 A/B 复测，以判断问题是否随板卡变化。
